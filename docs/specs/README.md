# Feature specs

Each feature gets its own spec file here before any code is written, for example `01-csv-drop-and-raw-view.md`.

A spec should cover:

- **Goal:** what the user can do when it's done
- **Behavior:** inputs, outputs, and edge cases
- **Out of scope:** what this feature deliberately leaves out
- **Acceptance criteria:** how we know it works
- **Open questions:** anything still undecided

Implement from the spec. If something is ambiguous or missing, flag it and resolve it in the spec instead of guessing.
